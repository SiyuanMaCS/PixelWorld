# PixelWorld：CVPR 实验与分析方案

版本：2026-11-09。研究方案稿；历史主结果复用，新增独立 Codex smoke、官方评分集成和缺失 Physics-IQ 全量正在执行。文中“已完成”指有产物支持，“待做”指尚未得到结果。最新执行状态由运行目录状态文件记录；参数与 baseline 证据见 [OUTPUT_SPEC_AND_ABLATION_PLAN.md](OUTPUT_SPEC_AND_ABLATION_PLAN.md) 和 [FRONTIER_BASELINE_AUDIT.md](FRONTIER_BASELINE_AUDIT.md)。

本轮更新：语音/音画对齐不评。视觉质量采用现有视频上的自动指标为主：JEDi衡量分布质量，FVD作补充，MUSIQ提供逐run成像质量；全量人工视觉评分改为可选。模型生成协议保持原样。

2026-11-09候选整理：场景与控制包括WorldScore（镜头运动、视差与新显露区域）和WBench（动作控制、多轮导航与连续性）；具身包括WorldArena和RoboJudge；物理演化以Physics-IQ为主，PVBench为资源待确认的候选；视觉质量和镜头遵循采用VBench-I2V候选。已核实的`vbench2_beta_i2v`属于VBench++，不是VBench-2.0的物理维度，不能混用其榜单。Principia、AVGen-Bench和WorldModelBench不进入后续实验。候选能力地图不等于全部启动全量生成，已有smoke与冻结主结果保留。

正式benchmark的硬性准入条件：必须先找到前沿视频/世界模型在同一完整官方I2V或交互setting上的公开评测分数，列出模型版本、来源链接/表格、分数与指标、任务范围、prompt/评测版本及聚合口径。我们只生成和评测PixelWorld，直接引用别人的已发表分数；不运行、复现或重评baseline。只有旧模型分数、只有评测代码、或已经跑通生成smoke，都不足以通过准入。找不到可比前沿分数的benchmark不进入正式实验，也不以自行跑baseline补缺口。

当前选择：PVBench保留为物体状态/物理维度的补充benchmark候选；Principia已按用户要求排除，历史资源调研保留。Physics-IQ保留主实验。完整输入数量、公开资源状态与执行边界见 [PHYSICS_BENCHMARK_CANDIDATES.md](PHYSICS_BENCHMARK_CANDIDATES.md)。PVBench报告600组，但完整资源尚未确认可获取。新增运行规格分别按官方协议核实，不沿用未确认的MORPHEUS统一2.7秒建议。

**论文要回答的问题**

通用 coding agent 能否从真实首帧生成可信的后续视频？这种能力在物理演化、视觉呈现和语义遵循上分别达到什么程度，受输入模态、原生修订及输出规格怎样影响？我们用可执行程序、逐版 RGB 和工具记录解释结果，再针对无法解释的环节做小规模控制实验。

研究对象是 agent 写程序产生 RGB 视频的能力。它包含首帧分析、运动/事件表达、图像操作、几何与光照计算；这些计算方法是需要分析的生成策略。程序允许复用首帧像素、变换图像和使用解析数学，不调用学习型生成器或外部物理引擎。

建议标题：**PixelWorld: Understanding Coding Agents as Pixel World Models**。目前证据集中于真实物理场景 I2V；论文的结论范围与这个实验范围一致。

**先冻结比较设置，避免已有实验失去价值**

- 主结果复用既有 native-v1：GPT-5.6 / GPT-6.1 × Text / Vision-Agent，共四组完整 198-case 结果。每个会话保留自主分析、工具使用、调试、检查、修订和结束；不加入首次有效保存即停止、固定 review 或修订次数限制。
- 明确 native-v1 有观察/事件计划及报告要求。“原生”指在这个已指定的 harness 中自主运行，不是没有任务指令。首次保存是事后分析的时间点，不是新运行协议。
- 历史 Vision-Input 作为已有的中间访问条件，用于辅助拆解输入视觉与输出检查工具的开放效果；不再设置为新默认 track。条件差不等于实际使用视觉检查的因果收益。
- 最小 native-v2 与 fulltrace-v2 的八条结果单列。它们验证完整图片记录，并提供案例证据；任务文本与 v1 不同，不能合并成同一次主实验，也不能把差异直接当作模态或模型效应。
- 后续规格实验采用同一份冻结任务模板，仅改输出尺寸/FPS 字段，并重新生成该模板下的基准格。若改用 v2，整项配对实验都用 v2，不与旧 v1 基准直接相减。
- 完整历史日志能恢复多少就恢复多少。只有 stdout 投影而缺少真实图片返回证据的 run，读图行为标记 unknown；不从缺失事件推断模型未看图。
- 正式 benchmark 固定官方 evaluator、Verified 数据版本和 BPP-base。198 cases = 66 scenes × 3 views；5 秒、当前 256×144 / 4 FPS。单轮可被官方接受；我们不扩张四轮聚合。

**实验一：先建立三种质量的能力画像**

这是论文主结果。它同时防止“物理分高就像真实视频”和“视频看起来真实就符合物理”的过度推断。

| 维度 | 具体评什么 | 数据与方法 | 报告结果 |
|---|---|---|---|
| 物理演化 | 与真实过程的时空匹配；可见接触、支撑、持久性和状态变化 | 完整官方 198-case Verified 分及 spatial、weighted-spatial、spatiotemporal、MSE 分量；另做盲审可见物理问题 | 官方总分与分量；明显违规率和可判断覆盖率 |
| 视觉质量 | 整批生成视频与真实视频的特征分布距离；逐视频成像质量 | JEDi为主要分布指标、FVD补充；MUSIQ逐帧评分后汇总到run；具体对象/背景/连续性问题在trace案例中核查 | 每完整配置的JEDi/FVD，逐run和逐版MUSIQ；不把这些指标等同全部感知质量 |
| 语义遵循 | 描述中的动作、作用对象、方向/关系、事件次序是否实现 | 在查看生成结果前，仅从 BPP 和首帧为每 scene 写必要检查项；标记完成/部分完成/未完成/无法判断 | 必要事件全部完成率、逐项完成率、缺失/额外事件率 |

物理审核采用“明确违规 / 未观察到明确违规 / 无法判断”，不把无法判断当正确。静止视频可能没有明显穿模，但未实现请求动作；语义完成率必须同时报告。单帧未规定的弹性、释放速度或落地姿态，不用某一参考未来强行作唯一正确答案。

官方 score 已按真实重复试验差异归一化，仍是基于参考的时空指标；它没有独立覆盖照片真实感和完整的文本事件遵循。论文解释总分时同时展示分量。Verified实际使用`final_score_view`：逐场景/视角归一化三个IoU和逆MSE子分，分别clip到[0,1]，四项等权平均；不要与另一个Original/stable公式混用。具体公式见 [PHYSICS_IQ.md](PHYSICS_IQ.md#what-the-verified-score-measures)。

先计算GPT-6.1两track的首次和最终视频质量，共四个198-video组；再复用GPT-5.6两track最终结果。每组保留所有case及相同权重，不能因首次/最终RGB相同而从分布指标中删样本。JEDi使用V-JEPA特征上的核MMD；FVD使用I3D特征的Fréchet距离。两者是集合指标，不能拆成每条run的独立质量分，也不能只给一个中间候选计算“FVD收益”。逐版分析采用MUSIQ与实际像素/视频证据。

真实视频与PixelWorld使用统一5秒视窗、采样时间、尺寸、特征模型和样本数量。198条规模下FVD可能有较大的有限样本偏差；JEDi的少样本优势也不能直接保证此数据集稳定。固定实现与权重，缓存特征，按66场景成组重采样报告不确定性，并检查真实take-1/take-2距离及样本数敏感性。本轮只计算PixelWorld/真实参考的分析指标，直接引用已发表的baseline成绩，不生成或重评baseline；本地Seedance保留为已授权的定性视频对照，缺0055的事实不改变完整198-case主实验。

MUSIQ是无参考成像质量指标，VBench的imaging_quality维度也采用它。它可以产生逐run、逐候选分数，但不验证物理正确或运动连贯；FVD/JEDi也混合内容、外观和运动因素。因此具体结论仍与视频/trace核对，全量人工视觉评分不作为本轮前置要求。[JEDi论文与代码](https://github.com/oooolga/JEDi)及[VBench成像评分](https://github.com/Vchitect/VBench/blob/master/vbench/imaging_quality.py)作为实现依据。

所有198输入进入正式PixelWorld质量统计。Seedance本地v1缺0055，仅用于明确标记的197个共有case定性对照；不把它拼成完整官方baseline或重算其FVD/JEDi。正式表复用官方Seedance2.5的42.43±0.76、Wan2.2 14B的32.20±0.60，并注明公开重复统计与我们的单轮、原生尺寸/FPS差异。单个PixelWorld分数高于公开均值，不据此声称稳定胜出。

视觉展示提供两种视图：相同尺寸/4 FPS 采样用于比较形状、纹理和背景；各自原生 FPS 用于比较实际流畅度。采样用真实时间戳，不进行学习插帧。低 FPS 造成的跳动与对象突然变形分开标注。frame00 原样复制是提交约定，不能当模型学会保持首帧的证据；重点检查首次动态帧的对象和背景延续。

另用全部首帧构造 198 条静止视频，以及将全部最终视频作固定种子的时间乱序，作为外部指标诊断。它们不调用 agent，不反馈分数、不用于挑选提交。这项检查回答官方各分量对真实运动和时序的敏感性；结果单列为指标诊断。

**实验二：视觉能力具体改变了哪类生成，而不是只增加几分**

复用两模型的四组完整数据及两组历史 Vision-Input。不新增主生成。

1. 在读取模型输出前，为 66 scenes 标注任务需求：刚体位移、旋转、新表面显露、遮挡改变、多对象相互作用、形变/流体、光照/反射变化。允许多标签。这些标签依据首帧与 BPP，不把生成策略倒写成任务属性。
2. 对每 scene 配对比较 Text/Vision 的物理、视觉、语义差值，报告优势/劣势分布与场景 bootstrap。类别只是描述，不能以热力学 3 scenes、磁学 2 scenes 宣称普遍规律。
3. 对视觉有帮助/无帮助/有害的具体场景，读取定位掩码、事件参数、遮挡合成和 RGB。检查差异出现在初始程序、后续动态公式还是外观修订。
4. GPT-6.1 约 99.38% 的最终模态物理分差已经在首次有效保存时出现。先检验这种模式是否也出现在视觉/语义指标；首次保存前可能已经看图、处理资产和修改代码，不能把它改称“纯初始感知收益”。

两个已有对照作为分析起点：0002 中 Text 与 Vision 的落地姿态不同，但没有唯一真值；0140 中两者都生成烟，烟场表示不同。需要判断影响来自事件解释还是像素呈现，不能只由分数差下结论。

产物是一张“任务需求 × 模态差异”的图和若干带执行代码/像素证据的解释。若差异无法确定来源，保留 unknown，不为了故事强行分配瓶颈。

**实验三：原生修订到底改善了什么，为什么总体物理收益小**

主对象为 396 条 GPT-6.1 native-v1 runs；不改它们的提示。先补实验一的首次/最终视觉与语义分，再分析全部已有 RGB 候选。

修订单位定义为按保存时间排列的、内容发生变化的 RGB 视频版本。程序重执行、代码 AST 变化、检查图片更新、重新开会话分别计数。中间覆盖历史如果没有保留，标记缺失，不重建为模型实际保存的版本。

对每 run 记录：首次/最终质量向量，实际视频版本数，首次保存前/后耗时与可用 token，代码修改类型，以及有证据的候选图片检查。旧日志不能精确恢复分阶段 token 时留空，最终 output_tokens 不重复叠加 reasoning_tokens。

先把修改按可观察作用分类：状态/动态公式、几何/遮挡、纹理/光照、背景补全、编码/播放器/格式。然后逐个问题对应以下链条：

> 候选是否存在可确定的问题 → agent 是否明确指出 → 是否定位到对应对象/代码 → 修改是否落实 → 问题是否消失 → 是否引入新问题。

“存在问题”作为判错正类：漏检是未发现真实问题，误报是声称存在不存在的问题。报告时优先用这些中文名称，避免与“合格为正类”的相反约定混淆。无明确检查主张时记未观测，不能自动归为漏检。

| 解释 | 需要怎样的证据 | 对应结论 |
|---|---|---|
| 外观改善没有进入物理总分 | 同版本视觉盲审提高，事件保持，物理分基本不变 | 修订收益依赖质量维度，不能叫无效修订 |
| 局部修好、同时破坏其他内容 | 指定问题消失，新增形变/遮挡/状态问题有帧证据 | 修复有副作用，需要分析保留约束 |
| 指出了问题但修改没命中 | 明确检查主张、相关 diff、前后同问题仍存在 | 定位或修复执行瓶颈 |
| 对不存在的问题反复修改 | 独立核验否定问题，后续修改有真实成本 | 误报驱动的无益工作；没有核验证据时不能这样标 |
| 工作保障提交而非改变视频 | AST 改动只验证 tensor/PNG/播放器，RGB相同 | 工程验证成本，不能全称浪费 |

频率分析选择 24 个 scene 的固定中央视角、两个 track，共 48 条旧 run。按类别分层、固定种子，在看分数和版本收益前抽取：固体14、流体5、光学3、热力学1、磁学1。标注每条的全部可恢复候选。此前极值选出的 0035/0089/0110/0164 和新八条 fulltrace-v2 只用于机制案例，不用于估计发生比例。

恢复完整图片事件后，把输入图、裁剪资产、背景图和真正的输出候选检查分开。图片数量不等于检查轮数；模型自述不等于已收到图片。流程图的每条关系都要有保存版本、tool返回、相关代码或视频帧依据。

如果视觉或语义上存在稳定收益，即使物理均值很小，也报告它。只有发现某类检查经常没有收益后，才独立测试温和节省检查/一次成稿策略。该干预不覆盖原生主实验，现有初版也不冒充“禁止修订”的新实验。

**实验四：分辨率/FPS影响的是生成策略、呈现，还是计算负担**

这是当前真正缺少的新条件实验。只用已有 Physics-IQ 场景，不增加新 benchmark；这张曲线是控制实验，不作为子集排行榜。

使用 GPT-6.1 Vision-Agent，先在既有场景中按需求盲选 6 个：位移/接触、旋转、新显露背景、遮挡、多对象作用、流体/形变各一个；不足以唯一归类时按预先顺序指定。首帧输入固定256×144，BPP、工具、reasoning及原生自主行为固定。输出首帧按同一确定性缩放规则适配尺寸。

- 首轮三个格：256×144/4FPS、512×288/4FPS、256×144/8FPS，每段5秒，共18个新会话。包含同模板的新基准，以免把旧run随机差异或v1/v2差异当规格效果。
- 有信息量再扩展到相同6scenes、七个格和两个track：分辨率128×72、256×144、512×288、1024×576（4FPS）；FPS2、4、8、16（256×144）；基准格重合，6×7×2总计84个会话，首轮18个包含其中。先用同一个GPT-6.1-Sol配置，不扩成所有模型/benchmark的网格。
- 如需检验 Text/Vision 的规格差异，再对最能区分解释的两个格补 Text。当前不预先扩成完整模型×规格大矩阵。

记录三轴质量、交付成功率、首次/最终 tokens、agent壁钟、生成代码执行时间和峰值内存。API latency较不稳定，墙钟作为配套效率结果；代码执行时间和内存由固定环境重放测量，分开报告。

必须区分三个对照：

1. **新生成高分辨率 vs 低分辨率结果放大**：两者显示尺寸一致，判断新增像素是否带来细节/边界/遮挡改善。若只更平滑，不称能力提升。
2. **高FPS新生成 vs 同一高FPS视频降采样**：后者不改预测程序，前者可能改变事件时间表和表达策略。区分采样更密与预测本身更好。
3. **原生显示 vs 统一尺度评分**：分辨率变化会影响像素误差和锐度指标；同一场景同时做统一尺寸比较与目标尺寸外观比较。

检查高FPS是否重复填帧、运动是否按秒保持、快速接触是否获得更多有效阶段；分辨率上升是否仍仅变换原贴图、是否新增纹理或补全。允许复用像素，分析其作用而非直接判失败。

“分辨率上限”分成交付上限和质量上限：报告测试范围内每个规格的成功/严重视觉缺陷率与资源曲线。如果1024也通过，只能说已测到1024；如果失败，先分清API/环境失败、执行资源不足和画面质量崩溃。不给通用LLM的绝对上限。

**实验五：从实际失败中拆原子能力**

原子分析是对前三项现象的解释，不另起一套任务。先在实验三的代表性trace及具体反例中形成标签，再决定是否需要独立 probe。

| 环节 | 在原生run里具体看什么 | 无法判断时才做的最小probe |
|---|---|---|
| 输入落地 | 原图可见对象与代码掩码/位置/支撑是否一致；数字是测量还是假设 | 只给合法首帧，返回指定对象框/可见遮挡关系；与独立标注比较，Text/Vision使用同一题 |
| 演化表达 | 程序是否实现请求事件、顺序和约束；检查真实执行状态，不只读注释 | 在同一case询问可观测事件顺序/已知与未知参数；只评能从输入确定的部分 |
| 程序落实与绘制 | 执行轨迹是否符合公式，合成遮挡是否与执行状态冲突，背景是否重复/残影 | 固定已有动态公式，仅改已明确错误的合成/掩码模块后重放；检查受影响像素与原问题，不反馈到主生成 |
| 自查与修复 | 对具体真问题/假问题的检查主张、定位、diff和前后像素 | 单独给同候选与固定检查问题，比较纯代码像素分析/多模态判错；属于独立诊断，不冒称原生行为 |

这些环节可同时失败。没有真实状态标签或代码未暴露相关量时留 unknown；不能仅凭低分推断“不会物理”，或因为独立probe通过就断言它是原生失败的原因。若做代码模块干预，精确重放原RGB后只改一个模块，报告变化与副作用。独立probe最多先12项×两种访问条件=24次短调用，不做新完整视频。

可参考 [AgentBoard](https://papers.nips.cc/paper_files/paper/2024/file/877b40688e330a0e2a3fc24084208dfa-Paper-Datasets_and_Benchmarks_Track.pdf) 的过程进展分析，以及 [APTBench](https://arxiv.org/abs/2510.24397) 从任务/轨迹构造原子探测的方式。这里的标签必须由真实像素生成问题产生，不能把通用agent技能表直接当实验证据。

**V2V：回答可观测信息的作用，作为有条件的扩展**

保留这个方向，不把它挤进必做主线。已有0033 smoke说明稀疏12帧历史只在最后一帧出现球，速度不可由位移确定；密集90帧历史中原生代码确实进行了定位和速度拟合。它不能证明V2V总体更好。

后续若需要解释运动状态瓶颈，选择6个有可见运动历史的已有case，比较同一预测边界下“历史末帧”与“完整合法3秒历史”，最多12个新视频，后续仍为5秒。原生agent自己选怎么利用历史，不提供准确速度提示。检查事件时间、状态估计和三轴质量。先核验Verified条件素材与切分边界；当前少量Original素材与switch图相同，不构成全量Verified V2V证据。完整官方V2V分数需要另行完成完整合法条件集，不用这12段代替。

**统计、成本与结论边界**

- 正式成绩全量198；场景是统计单位，按66 scenes分组bootstrap，三个视角不当独立重复。
- 质量配对和修订增益报告提高/持平/退步分布；改动次数、tokens与增益的关联只作描述，难任务会诱发更多修改。
- 局部因果解释依赖相同状态/程序的单模块干预。不同会话随机结果、自然选用工具与结果的关联，都不自动成为因果结论。
- 保留交付、隔离、格式、内容问题的区分；技术失败和内容失败分开，不能先丢弃低质量候选再比较。
- 所有质量标签、分析反馈、参考视频、eval masks和Seedance视频在生成workspace外；不做best-of-N挑提交，不用测试参考调提示来提高正式榜单分。
- 成本先报每run实际API usage、模型配置和执行资源。output_tokens含reasoning的API不重复累加；API未上报或旧日志无法恢复的字段标记缺失。

**执行顺序与可审核交付**

| 优先级 | 工作 | 新视频生成 | 完成后应得到的研究判断 |
|---|---|---:|---|
| P0 | 冻结主数据、制定首帧/BPP检查项、全量三轴质量评估；指标静止/乱序诊断 | 0个agent视频 | 44–45分的视频到底在哪些维度可信；与Seedance有怎样的质量差异 |
| P1 | 模态分解、首次/最终质量对比、48条代表性run逐版trace标注 | 0 | Vision帮助何类生成；修订改善外观、事件、物理中的哪一项，损失在哪里 |
| P2 | 规格三格smoke；有信号再扩七格 | 先18；扩展后累计84 | 质量/成本随像素和时间采样如何变化，是否有可用规格边界 |
| P3 | 只针对尚未解释的环节做原子probe；需要时再做V2V | probe先24次短调用；V2V至多12段 | 支持或否定具体瓶颈解释 |

先交付P0/P1，不为了凑工作量把所有可选实验同时启动。到这一步若发现修订在视觉或语义上有用，论文按事实改写；若所有维度收益都小，再做节省修订策略。当前数据不能预先锁定这项结论。

分析网页按研究问题组织：每个case显示输入/BPP、三轴标签、首版/中间/最终同步播放、代码diff、实际收到的检查图、阶段耗时/tokens，以及“可证事实/未知”。逐版图文与视频是机制证据入口；正式表与个案诊断分开。

**对应CVPR正文的叙事顺序**

| 正文章节 | 要回答的读者问题 | 核心图表 |
|---|---|---|
| Introduction | 写代码能否从真实图片预测视频，为什么值得研究？ | 一张同输入下PixelWorld/Seedance的视频与可执行生成示意图 |
| Setting and Evaluation | agent得到什么、允许什么、三种质量如何评？ | 输入隔离/原生流程；官方protocol与版本表 |
| Generative Capability | 物理、视觉、语义分别达到什么水平？ | 全量物理表；三轴质量与具体视频对照 |
| What Determines Quality? | Text/Vision、任务需求、尺寸/FPS怎样改变能力？ | 配对场景差异；规格质量/资源曲线 |
| Inside Native Generation | 程序怎样生成、怎样改、问题在哪个可验证环节？ | 逐版质量轨迹；修改类别与成功/副作用；单模块解释证据 |
| Discussion | 证据支持哪些能力、尚不能支持哪些世界模型主张？ | 可用范围、失败/不确定性、可复现分析资料 |

参考《Solve Vision with Code》的“统一设置与完整结果→读实际程序解释成败→效率与能力边界”顺序。其论文明确把规则评测范围与一般视觉能力区分；PixelWorld在真实视频上需要补齐视觉/语义审核和可见物理约束，才能让读者理解官方分数。现有数据不提供它的ID/OOD切分，不仿造这个结构。

参考《Physics of Language Models》的是形成证据链的方法：观察现象、提出竞争解释、设计能区分解释的实验、根据结果收敛。当前可检验的解释包括“多模态改变事件理解或绘制”“修订偏向外观而物理指标不变”“输出像素量增加主要增加执行负担”。它们是待检验的解释，不是准备提前写进摘要的发现。

**达到论文证据要求还缺什么**

已有基础是全量量化结果、真实程序/RGB归档和原生修订记录。最关键的缺口是统一视觉/语义评价、代表性trace解释、受控规格曲线。完成后，贡献可以落在一种真实I2V生成范式及其可解释的能力研究；单靠接近Seedance的物理分或若干可播放demo，还不足以支撑同样广的主张。VBench-I2V与PVBench保留为补充评测候选，按完整官方资源和协议准备，不以新增benchmark数量代替生成能力与机制分析。
